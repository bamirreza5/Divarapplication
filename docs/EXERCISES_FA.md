# تمرین‌ها و توسعه مرحله بعد

این موارد تمرین پیشنهادی هستند و در کد فعلی وجود ندارند. برای حفظ سبک بودن پروژه، هر بار یک قابلیت اضافه کنید.

| سطح | تمرین | معیار پذیرش |
| --- | --- | --- |
| ساده | فیلد برند | در ثبت، ویرایش و جزئیات ذخیره و نمایش داده شود |
| ساده | فیلتر فقط عکس‌دار | فیلتر در صفحه‌بندی حفظ شود |
| ساده | شمارش آگهی‌های هر دسته | فقط آگهی عمومی شمارش شود و تعداد کوئری با تعداد دسته رشد نکند |
| متوسط | علت رد آگهی | مدیر وارد کند، فقط مالک آن را ببیند |
| متوسط | گالری تا سه تصویر | هر عکس بررسی شود و محدودیت تعداد در سرور اعمال شود |
| متوسط | گزارش تخلف | عضو گزارش کند؛ هر کاربر برای هر آگهی یک گزارش فعال داشته باشد |
| متوسط | انقضای آگهی | آگهی منقضی عمومی نباشد؛ تست با زمان ثابت نوشته شود |
| پیشرفته | پاک‌سازی تصویر بی‌استفاده | ابتدا dry-run گزارش بدهد، سپس فقط فایل بدون ارجاع حذف شود |
| پیشرفته | جست‌وجوی فارسی بهتر | نمونه‌هایی با ی/ک عربی و فارسی یکسان پیدا شوند |
| پیشرفته | محدودسازی تلاش ورود | تعداد درخواست و کلید شناسایی روشن باشد؛ خطای قابل فهم برگردد |

## نمونه مسیر توسعه «علت رد»

1. فیلد `rejection_reason` را به `Ad` اضافه کنید.
2. migration بسازید و روی دیتابیس محلی اعمال کنید.
3. فیلد را در فرم مدیر نمایش دهید؛ آن را به فرم عمومی مالک اضافه نکنید.
4. فقط در صفحه «آگهی‌های من» و برای وضعیت ردشده آن را نمایش دهید.
5. با دو حساب بررسی کنید که علت رد به کاربر دیگر نشت نکند.
6. تست دسترسی و تست ذخیره متن اضافه کنید.

## پرسش‌های بحث و ارزیابی

- آیا وجود `login_required` برای محدودکردن ویرایش کافی است؟ چرا؟
- چرا برای نشان از مدل جداگانه و قید یکتا استفاده شده است؟
- آیا گرفتن شماره تماس بعد از ورود به معنای غیرقابل استخراج بودن شماره است؟ خیر؛ توضیح دهید چه چیزی کنترل شده است.
- با حذف آگهی، فایل تصویر روی دیسک چه می‌شود؟
- چرا قیمت توافقی صفر نیست؟ فرق NULL و صفر در فیلتر چیست؟
- چه زمانی جست‌وجوی `icontains` برای داده فارسی کافی نیست؟
- در صورت افزایش کاربران، چه شواهدی برای تغییر SQLite لازم دارید؟

## معیار کیفیت برای قابلیت جدید

- سناریوی واقعی و خروجی قابل مشاهده داشته باشد.
- مجوز دسترسی در سمت سرور بررسی شود.
- داده نامعتبر پیام روشن بدهد.
- قالب موبایل قابل استفاده بماند.
- تست، رفتار یا خطر واقعی را بررسی کند و صرفاً خطوط پیاده‌سازی را تکرار نکند.
- دستور اجرا و تغییر مدل در مستندات به‌روز شود.
