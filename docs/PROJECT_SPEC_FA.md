# صورت پروژه: سامانه ثبت آگهی دیوارک

## هدف آموزشی

ساخت یک برنامه کامل اما کوچک با معماری معمول Django. هنرجو باید بتواند مسیر یک درخواست را توضیح دهد، رابطه‌های دیتابیس را طراحی کند، داده ورودی را بررسی کند و دسترسی به اطلاعات را در سمت سرور محدود کند.

پیش‌نیاز: آشنایی مقدماتی با Python، تابع، کلاس، HTML، فرم و SQL. برای اجرای اولیه نیازی به یادگیری ابزارهای فرانت‌اند ندارید.

## نقش‌ها

| نقش | امکانات |
| --- | --- |
| مهمان | دیدن آگهی‌های منتشرشده، جست‌وجو و ثبت‌نام |
| کاربر عضو | امکانات مهمان، ثبت آگهی، مدیریت آگهی خودش، نشان‌کردن و درخواست شماره تماس |
| مدیر | مدیریت کاربران، شهر و دسته؛ تأیید/رد آگهی در Django Admin |

## صفحات

| نشانی | صفحه | نیاز به ورود |
| --- | --- | --- |
| `/` | فهرست، جست‌وجو و فیلتر | خیر |
| `/ads/<id>/` | جزئیات آگهی عمومی؛ آگهی خصوصی فقط برای مالک | برای عمومی خیر |
| `/ads/new/` | ثبت آگهی | بله |
| `/ads/<id>/edit/` | ویرایش | فقط مالک |
| `/ads/<id>/delete/` | تأیید حذف | فقط مالک |
| `/my-ads/` | مدیریت آگهی‌ها | بله |
| `/bookmarks/` | آگهی‌های نشان‌شده فعال | بله |
| `/accounts/register/` | ثبت‌نام | خیر |
| `/accounts/login/` | ورود | خیر |
| `/admin/` | پنل مدیر | مدیر |

نشانی‌های «فروخته‌شده»، «نشان» و «تماس» عملیات با روش POST هستند؛ بازکردن آن‌ها با GET عملیات را انجام نمی‌دهد.

## اطلاعات هر آگهی

| فیلد | قاعده |
| --- | --- |
| عنوان | ۵ تا ۱۲۰ نویسه |
| توضیحات | ۲۰ تا ۵۰۰۰ نویسه |
| دسته و شهر | انتخاب از داده‌های مدیر |
| محله | اختیاری، حداکثر ۸۰ نویسه |
| نوع قیمت | مشخص، توافقی یا رایگان |
| قیمت مشخص | عدد صحیح مثبت، حداکثر ۹۹۹٬۹۹۹٬۹۹۹٬۹۹۹ تومان |
| قیمت توافقی | مقدار ذخیره‌شده NULL |
| رایگان | مقدار ذخیره‌شده صفر |
| تلفن | شماره همراه ۱۱ رقمی با شروع ۰۹؛ ارقام فارسی/عربی پذیرفته می‌شوند |
| تصویر | اختیاری، یک تصویر تا ۳ مگابایت و حداکثر ۱۶ میلیون پیکسل |
| مالک | از کاربر واردشده؛ قابل تعیین از فرم عمومی نیست |
| وضعیت | توسط سرور و مدیر؛ قابل تعیین از فرم عمومی نیست |

تصویر به JPEG تبدیل، تا حداکثر ۱۶۰۰×۱۶۰۰ کوچک و با نام تصادفی ذخیره می‌شود. این کار مقدار metadata و نام اصلی فایل را حذف می‌کند.

## قواعد انتشار

- آگهی جدید در انتظار تأیید است.
- مدیر می‌تواند آگهی در انتظار یا ردشده را منتشر کند.
- مدیر می‌تواند آگهی در انتظار یا منتشرشده را رد کند.
- ویرایش هر آگهی، حتی فروخته‌شده، آن را دوباره به «در انتظار تأیید» می‌برد.
- فقط مالک آگهی منتشرشده می‌تواند آن را فروخته‌شده کند.
- فقط آگهی منتشرشده در جست‌وجو و نشان‌ها نمایش داده می‌شود.
- وضعیت خصوصی فقط برای مالک در صفحه جزئیات قابل مشاهده است. مدیر برای بررسی از پنل مدیریت استفاده می‌کند.

## سناریوهای پذیرش

1. کاربر جدید ثبت‌نام می‌کند، آگهی می‌سازد و آن را در «آگهی‌های من» می‌بیند.
2. مهمان آگهی تأییدنشده را نمی‌بیند و بازکردن مستقیم نشانی آن پاسخ 404 می‌دهد.
3. مدیر آگهی را تأیید می‌کند؛ آگهی در صفحه اصلی ظاهر می‌شود.
4. کاربر دوم می‌تواند آگهی عمومی را نشان کند و با درخواست تماس شماره آن را ببیند.
5. کاربر دوم با تغییر شناسه در URL نمی‌تواند آگهی مالک را ویرایش، حذف یا فروخته‌شده کند.
6. جست‌وجو با شهر، دسته، متن و مبلغ فارسی هم‌زمان کار می‌کند.
7. قیمت توافقی در فیلتر بازه مبلغ حذف و در مرتب‌سازی مبلغ در انتهای فهرست قرار می‌گیرد.
8. حذف ابتدا صفحه تأیید دارد و فقط با POST انجام می‌شود.
9. ویرایش آگهی منتشرشده باعث خروج آن از فهرست عمومی تا تأیید مجدد می‌شود.
10. صفحه اصلی و فرم‌ها در موبایل بدون اسکرول افقی قابل استفاده‌اند.

این پروژه جریان آموزشی خریدوفروش آگهی را نشان می‌دهد و پلتفرم عملیاتی در مقیاس دیوار نیست. توسعه‌های بعدی را جداگانه و با معیار مشخص اضافه کنید تا خوانایی پروژه حفظ شود.
