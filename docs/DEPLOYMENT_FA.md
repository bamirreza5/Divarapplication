# محدوده نسخه آموزشی و استقرار

## اجرای فعلی

تنظیم پیش‌فرض برای اجرای محلی است: DEBUG روشن، دیتابیس SQLite و میزبان‌های localhost. کلید پیش‌فرض صرفاً برای همین محیط است. اسکریپت‌های اجرا داده نمونه می‌سازند و از `runserver` استفاده می‌کنند.

نسخه عمومی نیاز به تصمیم عملیاتی جداگانه دارد؛ هیچ استقرار اینترنتی همراه این بسته انجام نشده است.

## متغیرهای محیطی

پروژه متغیرهای سیستم‌عامل را می‌خواند و فایل `.env` را به‌صورت خودکار بارگذاری نمی‌کند.

| متغیر | کاربرد |
| --- | --- |
| `DJANGO_DEBUG` | `true` برای محلی؛ `false` برای انتشار |
| `DJANGO_SECRET_KEY` | کلید تصادفی؛ در حالت DEBUG=false اجباری است |
| `DJANGO_ALLOWED_HOSTS` | میزبان‌ها با جداکننده کاما |
| `DJANGO_CSRF_TRUSTED_ORIGINS` | Originهای HTTPS مجاز با جداکننده کاما |
| `DJANGO_DB_PATH` | مسیر دیتابیس SQLite؛ پیش‌فرض پوشه پروژه |

نمونه PowerShell برای بررسی تنظیمات انتشار:

```powershell
$env:DJANGO_DEBUG="false"
$env:DJANGO_SECRET_KEY="<یک کلید بلند و تصادفی واقعی>"
$env:DJANGO_ALLOWED_HOSTS="ads.example.com"
$env:DJANGO_CSRF_TRUSTED_ORIGINS="https://ads.example.com"
.\.venv\Scripts\python.exe manage.py check --deploy
```

با DEBUG=false، کوکی‌ها Secure می‌شوند و درخواست HTTP به HTTPS هدایت می‌شود. تنظیمات HSTS و reverse proxy به محیط استقرار وابسته‌اند و باید با مشخصات سرور تنظیم شوند. مقدارهای نمونه را به‌عنوان کلید واقعی استفاده نکنید.

## کارهای ضروری پیش از انتشار عمومی

- آخرین اصلاحات شاخه Django و بسته Pillow را بررسی کنید؛ پس از ارتقا همه آزمون‌ها را اجرا کنید.
- سرور WSGI/ASGI عملیاتی و HTTPS تنظیم کنید؛ `runserver` برای تولید نیست.
- فایل‌های static را با `collectstatic` جمع کنید و static/media را با سرویس مناسب ارائه دهید.
- برای media محدودیت حجم در وب‌سرور و فضای ذخیره‌سازی تعیین کنید؛ تنظیم حافظه Django جای محدودیت کامل وب‌سرور را نمی‌گیرد.
- از دیتابیس و media پشتیبان‌گیری و بازیابی آزمایشی انجام دهید.
- ظرفیت، هم‌زمانی و نیاز به PostgreSQL را با داده و اندازه واقعی بررسی کنید.
- محدودسازی تلاش ورود و ثبت آگهی، گزارش تخلف و سیاست رسیدگی را اضافه کنید.
- حساب `demo` را حذف و از داده ساختگی برای معامله استفاده نکنید؛ `seed_demo` در حالت DEBUG=false اجرا نمی‌شود.
- لاگ خطا، پایش سلامت و پاک‌سازی امن فایل‌های قدیمی را تنظیم کنید.

## محدودیت‌های مشخص

1. حساب با نام کاربری و رمز است؛ تأیید تلفن با پیامک ندارد.
2. شماره تماس پس از ورود قابل دریافت است؛ این سازوکار جلوی استخراج توسط کاربر واردشده را به‌طور کامل نمی‌گیرد.
3. یک عکس برای هر آگهی وجود دارد؛ فایل‌های قدیمی پس از حذف یا تعویض عکس به‌صورت خودکار پاک نمی‌شوند.
4. آگهی خصوصی در سایت عمومی محدود است؛ فایل media با URL مستقیم، کنترل دسترسی جداگانه ندارد. برای media خصوصی باید View/ذخیره‌سازی محافظت‌شده اضافه کنید.
5. تاریخ‌ها میلادی و منطقه زمانی تهران است؛ تقویم شمسی تعاملی وجود ندارد.
6. جست‌وجوی فارسی بر پایه `icontains` است؛ یکسان‌سازی حروف عربی/فارسی و رتبه‌بندی زبانی ندارد.
7. چت، پرداخت، نقشه، API عمومی، انقضای خودکار و بازیابی رمز ایمیلی پیاده‌سازی نشده‌اند.
8. «مدیر» در سناریوی ساده، superuser محلی است. برای تیم واقعی مجوزهای حداقلی و Groupهای Django تعریف کنید.

این محدودیت‌ها انتخاب آگاهانه برای خوانایی و سبک بودن پروژه‌اند؛ معیار توسعه بعدی، نیاز واقعی و تست رفتار اضافه‌شده است.
